# Toolkit and libraries — what exists, what to add, how to mix

Three layers. Decide top-down:
1. **Art direction and method** (this skill) — decides _what_ the page should do. No library fixes a
   weak decision.
2. **Specialised engines** — GSAP, three.js, Rive, Lenis, Radix, Rapier, Howler… Use one when the
   project already has it, or when it provides a capability the layers below lack.
3. **@snowbros/\*** — small primitives that share one ticker, one scroll model, one cleanup model,
   and adapters that let layer-2 engines join that model instead of competing with it.

Hard rule: **one owner per concern.** One scroll model, one rAF loop, one engine animating a given
element's property. Mixing engines is fine; two engines writing `transform` on the same element is
not.

## Library decision matrix

Use when the condition holds _and_ the toolkit row says the capability is missing or the project
already uses the library.

| Library                | Gives                                                              | Use when                                                                                 | Don't when                                                                     | Mix with SNOWBROS via                                                   |
| ---------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **GSAP** (+ SplitText) | Mature timeline authoring, rich easing, SplitText with masks, Flip | Long authored sequences; the project already uses it; you need SplitText masks/autoSplit | A three-property hover; as a second engine on elements `motion` already drives | Create timelines **paused**; drive with `scrub(fromGsap(tl), progress)` |
| **GSAP ScrollTrigger** | Scroll triggers, pinning, snapping                                 | The project is GSAP-first and has no other scroll model                                  | Alongside `scrollProgress`/`pin` on the same page                              | Pick one scroll model; if ScrollTrigger, skip `pin`                     |
| **Lenis**              | Smoothed wheel scroll on desktop                                   | Long cinematic scroll pages on desktop where wheel steps feel jerky                      | Product UI, touch devices, reduced motion; never with Locomotive Scroll        | `smoothScroll({ create: () => new Lenis() })`                           |
| **three.js**           | 3D/WebGL rendering                                                 | A signature object or scene that carries the idea                                        | Decoration CSS/SVG can do                                                      | `@snowbros/scene` stage lifecycle                                       |
| **React Three Fiber**  | Declarative three in React                                         | The project is React and the scene has many components/state                             | Vanilla/Vite sites; a single object                                            | Stay inside R3F; use core springs/reduced motion only                   |
| **WebGPU / TSL**       | Compute, modern shading                                            | A feature WebGL cannot do, with a WebGL fallback path                                    | As a default renderer for broad audiences                                      | Feature-detect; `withFallback` for the static path                      |
| **Rive**               | Designer-authored, state-driven vector animation                   | Illustrated characters/marks whose states a designer must author                         | Geometric/procedural art you can draw in code (SVG/canvas is lighter)          | `driveRiveInput(input, progress)`                                       |
| **Radix UI** (React)   | Accessible dialog, menu, popover, tabs primitives                  | React projects building those components                                                 | Non-React stacks; one simple disclosure                                        | Animate their `data-state` with CSS or `motion`                         |
| **Rapier**             | Physics simulation (WASM)                                          | Interaction _is_ physics (stacking, collisions, vehicles)                                | Springy UI — springs from `core` are enough                                    | `stepPhysics(world, { hz, isAsleep })`                                  |
| **Howler.js**          | Audio sprites, playback, unlock handling                           | Sound is part of the experience, always opt-in with a visible toggle                     | Autoplaying sound; UI clicks by default                                        | `soundCues({ cue: new Howl(…) })` — off until opted in                  |

Lesson: none of them is "a library". Each pairs one signature technique with strong art direction,
and keeps the rest of the page conventional and fast.
